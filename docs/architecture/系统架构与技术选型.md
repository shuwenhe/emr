# 系统架构与技术选型（第三步）

## 1. 架构分层
- 设备接入层：采集、校准、数据上传
- 数据与存储层：对象存储 + 关系/时序数据库
- 计算与算法层：预处理、热层析重建、AI特征
- 业务与规则层：融合评估、灸疗推荐
- 报告与分发层：模板渲染、版本固化、分发
- 监控与运维层：日志、指标、告警、审计

## 2. 服务拆分
- 设备管理服务
- 数据接入服务
- 预处理与QC服务
- 热层析重建服务
- AI推理/特征服务
- 评估与规则引擎服务
- 报告生成服务
- 灸疗方案服务
- 用户与权限服务

## 3. 数据流设计
- 采集端 → 接入服务 → 对象存储
- 元数据 → 关系数据库
- 预处理结果 → 中间存储
- 算法输出 → 报告服务
- 报告与方案 → 分发端

## 4. 技术选型（建议）
### 存储
- 对象存储：MinIO/S3
- 关系数据库：PostgreSQL
- 时序数据：TimescaleDB 或 InfluxDB

### 计算与任务调度
- 任务队列：RabbitMQ 或 Kafka
- 任务编排：Celery/Argo Workflows
- 计算框架：Python + NumPy/PyTorch

### 服务与接口
- 后端框架：FastAPI / Django
- API协议：REST + gRPC（内部）
- 权限：JWT + RBAC

### 前端与报告
- 前端：React/Vue
- 报告渲染：HTML模板 + PDF生成

### 运维与监控
- 日志：ELK 或 Loki
- 监控：Prometheus + Grafana

## 5. 选型依据
- 计算密集型算法优先使用Python/CUDA
- 数据规模大优先对象存储
- 业务扩展优先微服务+消息队列
