# 设备接入接口

## POST /ingest
用于上传红外设备数据与采集元数据。

### 请求
- Content-Type: multipart/form-data
- 表单字段：
  - file: 红外数据文件
  - metadata: JSON 字符串

### metadata 示例
```json
{
  "device": {
    "device_id": "dev-001",
    "model": "IR-600",
    "firmware": "1.0.3"
  },
  "capture": {
    "capture_time": "2026-02-10T08:30:00Z",
    "frame_rate_hz": 15,
    "resolution": "640x480",
    "spectral_range": "8-14um",
    "distance_m": 1.2,
    "emissivity": 0.98
  },
  "environment": {
    "ambient_temp_c": 24.5,
    "humidity_percent": 45
  },
  "patient": {
    "patient_id": "P0001",
    "name": "张三",
    "gender": "male",
    "age": 45,
    "body_part": "shoulder"
  },
  "clinical": {
    "chief_complaint": "肩颈酸痛三个月",
    "past_history": ["慢性颈肩劳损"],
    "allergies": ["无"],
    "medications": ["无"],
    "diagnosis": "颈肩部肌筋膜紧张",
    "doctor_opinion": "建议结合临床体征，必要时进一步影像检查"
  },
  "tags": ["baseline", "session-1"]
}
```

### 响应
- record_id: 存储记录 ID
- storage_path: 文件落盘路径
- qc_issues: QC问题列表（为空表示通过）

## POST /analyze
根据已上传记录生成评估报告与灸疗方案。

说明：生成报告后会自动创建/更新该记录对应的电子病历（EMR）。

### 请求
- Content-Type: application/json
- Body:
```json
{
  "record_id": "<ingest返回的record_id>"
}
```

### 响应
- report: 评估报告
- plan: 灸疗方案
- dispatch: 下发给设备的指令payload
- payload_path: 原始数据文件路径
- history: 历史检测与报告摘要（按 patient_id 自动关联）
- report.thermal_marked_image: 红外带温度标记图片（自动生成）
- report.thermal_marked_labels: 识别到的温度标记文本与数值（OCR）
- report.analysis.regional_comparison: 基于平均体温的分区对比（high/low/normal）
- report.analysis.regional_comparison.abnormal_regions: 异常部位与温差依据

## POST /dispatch
将灸疗方案下发至设备（模拟）。

### 请求
- Content-Type: application/json
- Body:
```json
{
  "record_id": "<ingest返回的record_id>"
}
```

### 响应
- dispatch: 下发payload
- ack: 设备接收回执（queued）

## POST /device/ingest
用于设备直连场景（本地落盘模拟），自动采集并同步至平台。

### 设备落盘约定
- device-drop/子目录
- 子目录至少包含：metadata.json 与一个数据文件（.csv/.bin/.dat/.npy/.zip）

### 请求
- Content-Type: application/json
- Body:
```json
{
  "capture_path": "/path/to/device-drop/capture-001",
  "move_to_processed": true
}
```

说明：
- capture_path 为空时，扫描 device-drop 下所有待处理目录
- move_to_processed 为 true 时，处理完成目录会移动至 device-processed

### 响应
- ingested: 已入库的记录列表
- skipped: 跳过的目录列表

## POST /import/history
用于历史图像/数据批量导入与解析。

### 请求
- Content-Type: application/json
- Body:
```json
{
  "root_path": "/path/to/history",
  "analyze": true
}
```

### 响应
- ingested: 已入库记录
- skipped: 跳过目录
- analyzed: 自动分析结果（可选）

## POST /emr/generate
自动生成电子病历（EMR），与诊断报告数据联动。

### 请求
- Content-Type: application/json
- Body:
```json
{
  "record_id": "<ingest返回的record_id>"
}
```

### 响应
- emr_id: 病历 ID
- record_id: 记录 ID
- patient: 患者信息
- clinical: 病史信息
- diagnosis: 初步诊断
- doctor_opinion: 医生诊断意见
- thermal_images: 热成像图片路径
- report: 诊断报告数据
- treatment_plan: 治疗方案

## GET /emr/{emr_id}
获取单条病历。

## GET /emr
列出病历，可选参数：
- patient_id: 按患者 ID 过滤
- include_archived: 是否包含已归档（默认 false）

## PUT /emr/{emr_id}
编辑病历（诊断/医生意见/方案等）。

## POST /emr/{emr_id}/archive
归档/取消归档病历。

## 数据平台管理接口

### GET /platform/summary
返回平台数据汇总统计。

### GET /platform/records
查询采集记录列表（可选参数）：
- patient_id: 按患者 ID 过滤
- limit: 返回条数（默认 50）

### GET /platform/emrs
查询病历列表（可选参数）：
- patient_id: 按患者 ID 过滤
- limit: 返回条数（默认 50）
